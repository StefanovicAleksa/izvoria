# **Onyx AI Appliance 💎**

**Onyx** is an enterprise-grade, fully on-premise AI Appliance engineered specifically for Law Firms and Hospitals.  
Designed with absolute privacy in mind, Onyx provides a powerful audio intelligence and processing pipeline that operates securely on local hardware. No data ever leaves the premise, and organizations benefit from flat-rate, unlimited usage.  
⚠️ **Development Status:** Onyx is currently in active development. **This README reflects only the features currently implemented in the codebase.** Advanced features (like Vision processing, Vector RAG, and User Chat) will be added to this document as they are integrated.

## **🏗️ Current Features & Processing Pipeline**

Onyx operates autonomously, transforming raw media into highly accurate, domain-corrected transcripts. Here is a detailed breakdown of the currently implemented pipeline:

### **1\. Media Ingestion & Extraction**

* **What it does:** Securely monitors local directories, ingests raw video/audio files, and prepares them for AI processing.  
* **How it works:** Uses FFmpeg to isolate and extract a normalized, high-fidelity audio track (usually 16kHz WAV) from various media formats. It uses SHA-256 hashing to deduplicate files and prevent redundant processing.

### **2\. Voice Activity Detection (VAD)**

* **What it does:** Identifies exact timestamps where human speech occurs, discarding silence, background noise, or music.  
* **How it works:** Employs the **NVIDIA NeMo MarbleNet** model. This drastically saves compute time for downstream tasks, as the heavy transcription models are only fed audio segments containing actual speech.

### **3\. Discovery & Domain Adaptation (The "Scout")**

* **What it does:** Analyzes the audio to determine its context (Legal, Medical, or General) and generates a list of highly probable technical terms before the main transcription begins.  
* **How it works:** Uses a rapid, low-VRAM model (**Faster-Whisper Tiny**) to generate a rough draft of the audio. This draft is then passed through a text classifier (**DeBERTa v3**) to confirm the industry domain. Finally, it extracts "hotwords" (e.g., specific medications or legal statutes) to feed into the main transcriber.

### **4\. High-Fidelity Transcription**

* **What it does:** Converts the spoken audio into highly accurate, timestamped text.  
* **How it works:** Utilizes **Faster-Whisper Large v3**. By injecting the "hotwords" generated during the Scout phase as an initial prompt, the model is heavily biased toward correctly spelling complex industry terminology, drastically reducing hallucinations.

### **5\. Speaker Diarization**

* **What it does:** Answers the question "Who spoke when?" by clustering audio segments by speaker voice.  
* **How it works:** Uses **NVIDIA NeMo TitaNet** to analyze voice embeddings. It aligns these speaker tags (e.g., Speaker 1, Speaker 2\) with the text timestamps generated by Whisper.

### **6\. Post-Processing & Phonetic Correction**

* **What it does:** Reconstructs fragmented acoustic text into readable sentences and corrects lingering phonetic mistakes.  
* **How it works:** Uses the **SaT (Segment Any Text)** engine to fix grammar and sentence boundaries. Then, it uses a local LLM (**Qwen 2.5 7B Instruct**) cross-referenced against local domain glossaries to correct highly specific terms, maintaining a strict audit trail of any changes made.

## **🧠 The Orchestrator (VRAM Management)**

**The Challenge:** Onyx is designed to run locally. While target production hardware features 72GB of VRAM, our development environment is strictly constrained to **12GB VRAM** (e.g., RTX 3060). We cannot load the VAD, Whisper, Diarization, and Correction models simultaneously without crashing the system.  
**The Solution:** The **Model Orchestrator**.  
This core architectural component acts as a traffic controller for GPU memory, linking the features above together sequentially:

1. **Job Queueing:** The Orchestrator takes a media file and locks it for sequential processing.  
2. **Dynamic Swapping:** It loads MarbleNet (VAD) into VRAM, processes the audio, and **instantly unloads** it.  
3. It then loads Whisper Tiny (Scout) \-\> Unloads \-\> Loads Whisper Large v3 (Transcribe) \-\> Unloads \-\> Loads TitaNet (Diarization) \-\> Unloads.  
4. Finally, it loads Qwen 2.5 to do the text correction.  
5. **Result:** By enforcing strict lifecycle control and just-in-time loading, the Orchestrator ensures Onyx never exceeds the 12GB VRAM budget, maintaining absolute system stability.

## **🛠️ Setup Instructions**

Follow these instructions to set up the Onyx development environment. These steps assume you are running **Ubuntu 22.04 LTS**.

### **1\. System Prerequisites & Dependencies**

First, install the necessary OS-level packages, including FFmpeg for media processing and PostgreSQL for the relational database.  
sudo apt update  
sudo apt install \-y python3.10 python3.10-venv python3-pip  
sudo apt install \-y ffmpeg  
sudo apt install \-y postgresql postgresql-contrib

*Note: You must also have the **CUDA 12 Toolkit** and proprietary NVIDIA drivers installed. Refer to the official NVIDIA documentation.*

### **2\. Database Setup**

Create the required PostgreSQL user and database to match the default Onyx configuration.  
\# Log into the postgres prompt  
sudo \-u postgres psql

\# Run the following SQL commands:  
CREATE DATABASE onyx\_v2\_db;  
CREATE USER postgres WITH ENCRYPTED PASSWORD 'password';  
GRANT ALL PRIVILEGES ON DATABASE onyx\_v2\_db TO postgres;  
\\q

### **3\. Application Setup**

Clone the repository and install the strict Python dependencies within an isolated virtual environment:  
git clone \[https://github.com/your-org/onyx.git\](https://github.com/your-org/onyx.git)  
cd onyx  
python3.10 \-m venv venv  
source venv/bin/activate  
pip install \--upgrade pip  
pip install \-r requirements.txt

### **4\. Environment Configuration**

Create a .env file in the root directory. This must align with the parameters in app/core/config.py:  
\# Database Configuration  
POSTGRES\_SERVER=localhost  
POSTGRES\_PORT=5432  
POSTGRES\_DB=onyx\_v2\_db  
POSTGRES\_USER=postgres  
POSTGRES\_PASSWORD=password

\# Appliance Configuration  
ENV=development  
APP\_NAME="Onyx AI Appliance"

\# Domain Configuration  
APPLIANCE\_INDUSTRY=GENERAL  \# Options: GENERAL, LEGAL, MEDICAL  
APPLIANCE\_LANGUAGE=en

### **5\. Required Model Installation**

You must manually download and place the required AI models into the local models/ directory. The Orchestrator strictly expects these files to be present before booting. If a model is missing, the appliance will fail to start.

| Pipeline Step      | Model Name                  | Required Local Path                      | Est. VRAM |
|:-------------------|:----------------------------|:-----------------------------------------|:----------|
| **VAD**            | NeMo MarbleNet              | models/vad\_multilingual\_marblenet.nemo | \~1.2 GB  |
| **Scout**          | Whisper Tiny (English)      | models/whisper-tiny-en                   | \~0.2 GB  |
| **Classifier**     | NLI DeBERTa v3 X-Small      | models/nli-deberta-v3-xsmall             | \~0.2 GB  |
| **Transcription**  | Faster-Whisper Large v3     | models/faster-whisper-large-v3           | \~3.5 GB  |
| **Diarization**    | NeMo TitaNet Large          | models/titanet\_large.nemo               | \~0.5 GB  |
| **Sentence Split** | Segment Any Text (SaT)      | models/sat-3l-sm                         | \~0.75 GB |
| **Correction**     | Qwen 2.5 7B (GGUF Q4\_K\_M) | models/Qwen2.5-7B-Instruct-Q4\_K\_M.gguf | \~5.0 GB  |

### **6\. Running the Appliance**

Once the database is running and all dependencies/models are in place, initialize the appliance. This will trigger the Orchestrator to start listening for files.  
\# Ensure your virtual environment is activated  
source venv/bin/activate

\# Run the main application entry point  
python \-m app.main
